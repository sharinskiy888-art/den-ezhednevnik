Версия модуля `1.0.N` = сборка «Дня» N (АК-Сервер принимает только X.Y.Z).

## 1.0.111 — 30.10.2026
По ТЗ «АК-День 1.0.109 - единый стиль», редакция 30.10 19:20 (задача О, кнопка «Отправить»).

**Что сделано**
- Своя часть программы для монтажника: адрес `…/m/crm/worker/`. В ней только свои дела, поручения и назначенные заявки, без финансов, планов и копий данных. На телефоне ставится как приложение «АК-День Монтажник» (свой значок, работает с главного экрана), на компьютере открывается тот же адрес.
- `module.json`: поле `share` (`installer`, «Монтажник», `/worker`, телефон и компьютер), `external: ["/worker"]`, `public: []`, роль `installer` в `roles`. Части без входа нет: телефоны и адреса клиентов видят только участники заявки.
- Права проверяет сервер модуля по подписанным заголовкам ядра. Монтажника главный адрес переводит в его часть, клиентов он не правит, договоров ТО не видит. Всё, что нужно части (страница, файлы, обмен данными), идёт через один адрес `…/worker/`. Через него данные получает только монтажник; руководителя ссылка части переводит в главную программу. Служебные адреса ядра через этот адрес закрыты.
- Часть обновляется сама: после установки новой версии телефон при следующем открытии показывает новую версию, без новой ссылки. Новые автотесты: `tools/test-ak-part-update.js`, проверки в `tools/test-ak.js` и `server/tests/test_ak.py`.

## 1.0.106 — 28.10.2026
По ТЗ «АК-День → модуль crm».

**Что сделано**
- **Клиенты — в справочнике ядра `partners`**: каждое сохранение клиента уходит в `PUT /core/v1/partners/{id}` (полная запись, `rev`), удаление — `deleted:true`. Очередь отправки хранится в базе модуля и не теряется при перезапуске; ядро недоступно — «Клиенты» работают, отправка повторяется (10 с, 1 мин, 5 мин, 30 мин, раз в час). Конфликт `409` — берётся свежий `rev`; `400` — уведомление владельцу. Чужие изменения — событие `partner.changed` и проход по курсору при запуске и раз в 10 минут. Задачи, планы и финансы остаются в базе модуля. Телефоны и прочие поля клиентов в журнал не пишутся.
- **Перенос прежней установки**: при первом запуске (данных модуля ещё нет) берутся данные «Дня» из `C:\Users\<имя>\AppData\Local\Den\data` (или `C:\ProgramData\Den\data`) — база через копию и backup API с проверкой, фото. Прежняя папка только читается. Люди прежней установки переходят к сотрудникам ядра при первом входе: по email (логин или email в ядре), владельцу — данные единственного прежнего администратора.
- **Пакет без отдельного установщика**: `bash deploy/ak/build_module.sh` собирает `AK-Crm-Modul-1.0.106.zip` со своим Python 3.12 для Windows и запуском `crm.cmd`; ставится через «Установить программу из файла» / «Обновить» на плитке. Свой вход по email и паролю и окно первого администратора в модуле не показываются (как и раньше — вход только через ядро).
- `module.json`: `subscribes: ["partner.changed"]`, `start: "crm.cmd"`.

**Изменения базы** (миграция 7, только добавление): таблицы `core_outbox` (очередь отправки в ядро) и `core_links` (`rev` записи ядра). Прежняя версия работает на новых данных.

## 1.0.105 — 28.10.2026
Под ТЗ модуля редакции 2 (АК-Сервер 1.0.3).

**Что сделано**
- `min_core` 1.0.3, `start_timeout_sec` 120 (первый запуск exe на медленном диске).
- **«Восстановить из файла»** (только owner): окно «Аккаунт» → кнопка. Принимает общий архив АК `ak-….zip` (берётся последняя `modules/crm/<имя>/`) или свой zip одной копии. Порядок: проверка архива (zip, пути без `..` и ссылок, база `quick_check`, версия базы не новее модуля, место на диске) → текущие данные в `AK_DATA_DIR\before-restore-<дата>\` (хранятся 3) → копия на место → миграции → новая метка данных. Работает сразу, без перезапуска; при любой ошибке возвращается как было. Архив до 100 МБ, во время приёма лежит в `AK_DATA_DIR\tmp`, не в памяти.
- После восстановления устройства со старыми данными получают `409 data_restored`, забывают их и скачивают восстановленные (иначе «новее побеждает» вернуло бы на сервер всё, что было после копии).
- Страница переживает автоперезапуск: запрос без ответа, 502 или 503 повторяется один раз через 4 с.
- Ошибки — в stdout (`module.log` ядра): время, метод и адрес, текст и трассировка. Тел запросов, паролей и секрета там нет.
- Подпись: nonce 16–128 символов; `X-AK-User-Name` раскодируется как `quote_plus` (пробел = `+`).
- Сотрудники: справочник в формате `{items:[{id,rev,deleted,updated_at,data}], next_cursor, more}` (имя — в `data`); в списке исполнителей ещё и все, кто уже входил (имя — из `X-AK-User-Name`). Ядро не отвечает — список не пропадает.
- Свой экран ПИН в режиме модуля выключен: ПИН и выбор кассира — у ядра.

**Изменения базы**: столбец `users.name` (добавление; прежняя версия работает на новых данных). Метка данных — строка `epoch` в таблице `meta`.

## 1.0.104 — 27.10.2026
Первая версия модуля. Та же программа, что и отдельный сервер «День»: если ядро передало `AK_MODULE_SECRET`, она работает модулем.

**Что сделано**
- Вход только через АК-Сервер: свой экран входа, пароли и приглашения в режиме модуля выключены.
- Каждый запрос проверяется подписью ядра (HMAC-SHA256, ±60 с, nonce не повторяется 120 с). Без подписи — 401.
- Все адреса под `/m/crm/`; ссылки приложения относительные. Слушает только `AK_HOST:AK_PORT` (127.0.0.1).
- Роли из `X-AK-Roles`: owner и admin — руководитель CRM; только viewer — просмотр всего без правок; остальные роли — монтажник (видит назначенные ему заявки). Администратор «Дня» (обратная связь, сверка) — owner.
- Люди — сотрудники ядра. Ключ человека в поручениях и заявках — `<uuid>@ak`: не меняется и не совпадёт с чужим, даже если email в ядре сменят. На экране — имя из справочника `employees`; исполнителей выбирают кнопками с именами.
- Если в том же браузере в ядро вошёл другой сотрудник (в этой или другой вкладке), приложение переключается на его данные; данные прежнего ему не отправляются.
- Непонятное событие ядра принимается (2xx) и пропускается, чтобы не держать очередь событий.
- Служебные адреса: `/healthz`, `/ak/v1/busy`, `/ak/v1/stop`, `/ak/v1/backup` (копия в `AK_DATA_DIR\.backup\<имя>\`, хранятся 3 последние), `/ak/v1/events` (повтор `event_id` не обрабатывается дважды).
- Данные только в `AK_DATA_DIR`; `den.env` не читается; файлы программы не меняются. Свои ежедневные копии выключены — копии заказывает ядро.
- На телефоне левый нижний угол свободен для кнопки «АК».

**Изменения базы** (только добавление, прежняя версия работает на новых данных)
- Новая таблица `ak_events (event_id, type, received_at)` — принятые события ядра, хранятся 90 дней.
- Сотрудники ядра записываются в существующую таблицу `users` (без пароля, email = `<uuid>@ak`).

**Для отдельного сервера (без АК)** поведение прежнее; новое: `GET /api/ak/me` отвечает `{ak:false}`, `DEN_BACKUP_EVERY=0` выключает автокопии.

**Не передаётся в ядро:** записи справочников и события модуль пока не пишет (`emits` пуст), поэтому деньги и id в формате ядра не требуются. Внутри «Дня» CRM хранит деньги в копейках, личные финансы — в рублях (это данные устройства).
