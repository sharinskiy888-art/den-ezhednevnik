# День — ежедневник

PWA-планировщик (задачи, планы, финансы, совместные задачи, фото, синхронизация через Supabase).
Хостинг — GitHub Pages (https://sharinskiy888-art.github.io/den-ezhednevnik/), проект Supabase — "Den Planner".
Владелец не программист: объясняй по-русски простыми словами, любую аббревиатуру расшифровывай.

## Главное правило
**Единственный источник правды — репозиторий на GitHub (ветка main).** Любая сессия перед работой берёт оттуда
свежий код, а не использует старую копию (однажды чуть не откатили v90 до v71 из-за устаревшего архива).

## Структура
- `index.html` — разметка и все диалоги
- `app.js` — вся логика (задачи, планы, финансы, уведомления, обновления, резервная копия)
- `i18n-en.js` — английские переводы; `sync.js` — всё общение с Supabase (вход, задачи, расходы, файлы)
- `styles.css` — стили через CSS-переменные; `sw.js` — service worker (кэш «сначала сеть»)
- `version.js` / `version.json` — номер версии и список изменений (RU `notes`, EN `notesEn`)
- `tools/test-buttons.js` — автотест каждой кнопки в настоящем браузере (Playwright)
- `.github/workflows/check.yml` — проверка (синтаксис, версия, автотест); `pages.yml` публикует сайт ТОЛЬКО если проверка зелёная

## Версия — везде одинаковая (иначе ломается автообновление)
- `app.js`: `const APP_VERSION = 'N'` и `register('sw.js?v=N')`
- `index.html`: все `?v=N` (styles, sync-config, sync, i18n-en, app)
- `sw.js`: `CACHE = 'day-planner-vN'` и все `?v=N` в ASSETS
- `version.js` и `version.json`: `version: 'N'` + пункт в `notes` (и `notesEn`)
CI проверяет это сам, но проверяй и до пуша. Не повышай версию ради правок, не влияющих на работу (документация, агенты, CI).

## Правила
- После правок: `node --check app.js sync.js i18n-en.js`, затем `node tools/test-buttons.js` (нужен Playwright). Без зелёного теста не считать работу законченной.
- Новый экран/кнопку — сразу добавлять в `tools/test-buttons.js` (flows). Тест падает на неизвестных ошибках JS.
- Логотип — латинская `D`. Цвета — только через CSS-переменные. Фото — через Supabase Storage (bucket `attachments`), не base64.
- Слияние в `sync.js`: кто новее по `updatedAt` — тот побеждает; удаления — надгробия (tombstones). Локальные данные никогда не заменяются пустым ответом облака.
- Старые данные пользователей не имеют новых полей (так сломались «Планы» — не было `createdAt`): всегда читай поля с запасным значением.
- Секреты (ключи, пароли) в код не вставлять. Anon-ключ Supabase публичный по замыслу, доступ защищает RLS (Row Level Security — права по строкам).
- Бесплатный Supabase: 5 ГБ исходящего трафика в месяц; при превышении облако отвечает 402 и приложение показывает плашку. Следи за расходом.

## Под-агенты (`.claude/agents/`)
- `button-tester` — полный тест каждой кнопки (`node tools/test-buttons.js`, 4 режима + напоминания, приглашения, PIN, фото, финансы, копия, обновления). Только проверяет. Зови: «используй button-tester».
- `tester` — быстрая проверка после правок; `code-reviewer` — смотрит diff; `deploy-version-checker` — сверяет версию во всех файлах.
- `deployer` — по «залей» прогоняет проверки и, если чисто, делает git add/commit/push; при проблеме ничего не заливает.
