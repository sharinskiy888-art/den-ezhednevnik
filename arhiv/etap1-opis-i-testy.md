## Что сделано
- `server/API.md` — договор между `sync.js` и сервером: все адреса, коды ответов, поля, правила прав, настройки `den.env`, где что хранится, и таблица «какая функция `sync.js` куда переезжает».
- `server/tests/` — тесты. Они запускают настоящий сервер отдельным процессом и ходят в него по сети, как приложение. Так тесты не зависят от того, как сервер устроен внутри.
- `.gitignore` — `den.env` и папка данных никогда не попадут в репозиторий.

## Что проверяют тесты (главное)
- **Вход:** форма ответа как у Supabase (чтобы `sync.js` менялся минимально), подделанный и просроченный токен → «войдите снова», выход и смена пароля отзывают другие сессии, пароли хранятся scrypt с солью, лимит 5 неудачных попыток в минуту, регистрация только по приглашению, сброс пароля админом, перенос пользователей с прежними id.
- **Личные данные:** чужой не видит, не меняет и не удаляет; данные хранятся без изменений; больше 1000 строк отдаются целиком; одновременная запись с двух устройств без ошибок; плохие данные отклоняются целиком.
- **Поручения (закрытие дыры прав):** исполнитель меняет только статус (кроме «Завершено»), галочки подзадач, свои отчёты и историю; 14 видов подмены (текст, дата, вложение, «Завершено», напоминание организатора, чужой отчёт и т. д.) — каждый должен дать отказ. Организатор не может «принять» за приглашённого. Отказаться нельзя, выйти — только через просьбу организатору.
- **Файлы:** только участникам; попытки выйти из папки к базе (`..`, `%2e%2e`, `\`) блокируются; загрузка с прежним именем для переноса.
- **Служебное:** разрешение браузеру только с сайта «Дня», ответы API не кэшируются (иначе `sw.js` закэширует данные), сервер не стартует без секрета и второй раз на ту же папку, копии базы и файлов по расписанию, журнал без паролей и токенов.

## Решения, принятые по перепроверке
1. Если два таймера приложения одновременно обновят вход, человека не выкидывает (окно 10 с). Повтор старого токена позже — признак кражи, сессия отзывается.
2. Повторное создание того же поручения (ответ потерялся) — не ошибка, а обновление.
3. Строка `user_id`, которую сейчас шлёт `sync.js`, допускается и игнорируется: владелец всегда берётся из входа.
4. 51-й отчёт исполнителя может вытеснить самый старый (так сейчас работает приложение — хранит 50).
