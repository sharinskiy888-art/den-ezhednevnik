## Что сделано
**Сервер (`server/`):**
- `db.py` — база SQLite (надёжный режим записи WAL, защита от одновременной записи), настройки из `den.env`, защита от запуска двух серверов на одну папку данных.
- `access.py` — **все проверки прав в одном месте** (как в ТЗ): токен, сессия, «чужое не трогать», ограничение размера запроса 32 МБ, защита от перебора паролей.
- `auth.py` — вход, выход, обновление входа, смена пароля, регистрация только по приглашению, пользователи и приглашения для администратора. Пароли — scrypt с солью (стойкое шифрование из стандартного Python).
- `sync.py` — личные задачи и расходы: «кто новее — тот прав», удаления не воскресают.
- `backup.py` — копия базы и фото по расписанию, хранится N последних.
- `main.py` — сборка, ответы API не кэшируются, ошибки понятным текстом, раздача экранов только из разрешённого списка.
- `admin.py` — **управление из командной строки** (см. ниже).

**Приложение:**
- `sync.js` переписан под свой сервер; внешне для приложения ничего не поменялось. Одно общее обновление входа на все запросы — человека не выкидывает, если два запроса пошли одновременно.
- Регистрация — только с кодом приглашения; «Забыли пароль?» — подсказка обратиться к администратору (писем больше нет); добавлена смена пароля.
- Старая сессия Supabase сама сбрасывается, и приложение один раз просит войти тем же email.
- Обратная связь идёт на свой сервер (раньше — formsubmit.co).
- `sw.js` больше не кэширует ответы сервера (раньше мог показать старые данные).
- Удалён `reset.html` (страница сброса пароля по письму).

**Проверки:** в автопроверку GitHub (CI) добавлены тесты сервера и живая проверка; в автотест кнопок — 6 новых проверок (код приглашения, «Забыли пароль?», переезд облака, смена пароля).

## Как администратору управлять (на компьютере с сервером)
```
python -m server.admin users                         — список пользователей
python -m server.admin add почта пароль [admin]      — добавить (пароль от 8 символов)
python -m server.admin invite почта                  — код приглашения
python -m server.admin password почта новый-пароль   — сбросить пароль
python -m server.admin delete почта                  — удалить
python -m server.admin feedback                      — сообщения обратной связи
python -m server.admin backup                        — копия прямо сейчас
```

## Что важно знать
1. **Совместные задачи (поручения) и их фото пока не работают на новом сервере** — это этап 3. До переключения это не страшно: сайт работает на Supabase.
2. **Для работы в локальной сети нужен HTTPS** (защищённое соединение). Без него браузер не даст приложению PIN-код, офлайн-режим и установку (service worker). Это решим на этапе установки на компьютер.
3. Пароли Supabase перенести нельзя (другой способ шифрования) — при переезде администратор задаст 5 пользователям новые пароли, id останутся прежними, поэтому данные на телефонах не потеряются (проверено живым тестом).
4. Наружу в интернет сервер не открывается; секрет и пароли — только в `den.env`, он в репозиторий не попадает (проверяется тестом).
