## Как переезжает человек (сам, без действий с его стороны)
1. Открывает обновлённое приложение → просит войти → вводит email и пароль от администратора.
2. Телефон загружает на сервер **все свои** задачи, планы и финансы.
3. Из прежнего облака добирает записи, которых на телефоне не было. Более новая версия с телефона **не затирается** старой.
4. У организатора переносятся его поручения с фото и голосовыми отчётов (ссылки в отчётах не меняются).
5. Телефон сообщает серверу свои числа, сервер сравнивает со своими → **отчёт сверки**.

## Сверка (то, что требует ТЗ)
По каждому человеку и каждому его устройству сравниваются: число задач, планов, операций, сумма доходов и расходов **в копейках**.
Смотреть: `python -m server.admin reconcile` → «совпадает» / «РАСХОЖДЕНИЕ» / «нет отчёта», плюс итог переноса из Supabase (сколько поручений и файлов, ошибки).
Копейки считаются одинаково на телефоне и сервере (19,995 ₽ = 2000 коп.; простое умножение в браузере дало бы 1999 — проверено отдельным тестом).
**Настоящий отчёт сверки по вашим 5 людям** будет при переключении (этап 7): сейчас реальные данные ещё в Supabase.

## Принято по умолчанию (скажите, если надо иначе)
1. **Исполнители перенесённых поручений принимают их заново** (одно нажатие «Принять»). Причина: сервер не может проверить, принимал ли человек задачу в старом облаке, а иначе любого можно было бы «записать» в задачу без согласия. Статус, подзадачи и отчёты сохраняются.
2. Поручение переносит его организатор, когда сам войдёт. Пока он не вошёл — его поручения ждут в Supabase.
3. Людей лучше заводить с прежним id из Supabase (`add <email> <пароль> --id <id>`). Если без него — телефон сам перенесёт данные под новый id, но **PIN придётся задать заново** (приложение подскажет).
4. Окно переноса включается строкой `DEN_MIGRATION=1` в `den.env` на время переезда, потом выключается.

## Найдено перепроверкой и исправлено (главное)
- Одна «плохая» задача заставляла бы телефон каждые 2 минуты заново качать все фото из Supabase и съедать лимит 5 ГБ → теперь готовое запоминается, плохое пропускается, повтор через 2, 4, 8… минут, не больше 6 раз.
- Можно было бы «записать» чужого человека в задачу как принявшего → исполнители только приглашаются.
- Удалённая организатором задача вернулась бы со второго телефона → сервер помнит перенесённое.
- Расхождения копеек на экзотических записях чисел, зависание при недоступном облаке (теперь не дольше 20 с), одновременное обновление входа Supabase, проверка id в команде `add`.
