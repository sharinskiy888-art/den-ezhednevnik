## Зачем
«День» (ежедневник с финансами и совместными задачами) становится блоком экосистемы АК и быстрой CRM (системой учёта клиентов) для моего бизнеса: пожарная сигнализация, электрика, видеонаблюдение. Требования те же, что у всех блоков. Блок ставится и продаётся отдельно и работает на моём компьютере или своём сервере без чужого облака. Он написан на Python, как Учёт и Ритейл. С другими программами связывается только через договор «АК-Обмен v1». Код короткий, надёжный и быстрый.

Сейчас «День» работает на GitHub Pages и бесплатном Supabase (облачной базе с входом). Это ограничения (5 ГБ трафика в месяц, однажды уже была блокировка за лимит) и зависимость от чужого сервиса. От обоих уходим.

## 1. Стек (как у АК-Учёта)
| Что | Выбор | Почему |
|---|---|---|
| Язык | Python 3.12+ | Как Учёт и Ритейл |
| Веб-сервер | FastAPI + uvicorn | Как Учёт |
| База | SQLite в режиме WAL (журнал, не блокирующий чтение) с `busy_timeout`, без ORM (прослойки над базой), обычный SQL | Меньше кода. На VPS (арендованном сервере) при росте — PostgreSQL через тот же SQL |
| Пароли | `hashlib.scrypt` с солью (стандартная библиотека) | Без зависимостей |
| Токены входа | Свои, подписанные HMAC (стандартная библиотека), без библиотек JWT | Без зависимостей |
| Файлы (фото, голосовые) | Папка `files/` рядом с базой | Без облачного хранилища |
| Сборка | Nuitka + установщик по образцу Учёта | Единая установка в экосистеме |
| Тесты | `pytest` для сервера, `tools/test-buttons.js` (Playwright) для экранов | Уже есть |

**Внешних библиотек не больше 4:** fastapi, uvicorn, pydantic (идёт с FastAPI), pytest (только для тестов). Каждую сверх этого — только с моего согласия и с причиной.

## 2. Структура (один файл — одна задача, до 300–400 строк)
```
server/
  main.py      запуск, маршруты, раздача экранов PWA (веб-приложения со значком на экране)
  db.py        подключение, миграции (только добавление)
  auth.py      вход, приглашения, сброс пароля админом, лимит попыток
  access.py    ВСЕ проверки прав в одном месте (вместо RLS — защиты строк в Supabase)
  sync.py      синхронизация личных данных: задачи, планы, финансы, настройки
  shared.py    поручения (совместные задачи), отчёты, присутствие
  files.py     фото и голосовые, выдача только участникам
  crm.py       клиенты, объекты, заявки, ТО (техническое обслуживание)
  backup.py    автокопии базы и файлов
  obmen.py     АК-Обмен v1 (выключен по умолчанию)
  tests/
den.env        секреты и настройки (не в репозитории, не в архивах)
```

## 3. Безопасность (обязательно, с тестом на каждый пункт)
- **Права проверяются только в `access.py`.** На каждую таблицу тест: чужой пользователь не видит, не меняет и не удаляет чужие строки.
- **Поручения (закрыть дыру, отложенную ранее):** организатор меняет задачу целиком. Исполнитель меняет только статус, подзадачи и отчёты, но не владельца, не список участников и не текст задачи. Отказаться от поручения исполнитель не может, а выйти из задачи может только с согласия организатора **(по умолчанию)**.
- Пароли — scrypt с солью. Лимит попыток входа: 5 в минуту на адрес и email.
- Секрет подписи токенов, пароли и ключи — только в `den.env`.
- Фото и голосовые отдаются только участникам своей задачи или заявки.
- Телефоны и адреса клиентов не пишутся в логи и не уходят в «АК-Обмен».
- Наружу в интернет компьютер с Windows 10 не открывать.

## 4. CRM (этап 4)
**По умолчанию** (поменяю, если отвечу иначе):
- **Для кого:** для моего бизнеса, но без жёсткой привязки к пожарке, чтобы потом можно было продавать. Виды работ и систем — справочник, а не код.
- **Пользователи:** я (админ) и 2–5 монтажников. Монтажник видит только назначенные ему заявки и объекты.
- **Где:** раздел «Клиенты» внутри «Дня». Личные финансы и рабочие деньги разделены.
- **Сущности:**
  - **Клиент** — название или ФИО, ИНН (строкой), контакты, заметки.
  - **Объект** — клиент, адрес, системы (АПС — автоматическая пожарная сигнализация, СОУЭ — система оповещения и управления эвакуацией, видеонаблюдение, электрика), оборудование, фото.
  - **Заявка** — объект, тип (монтаж, ремонт, ТО, проект), этапы: «новая → КП (коммерческое предложение) → в работе → сдано → оплачено», исполнители, срок, сумма.
  - **Договор ТО** — объект, периодичность (по умолчанию раз в месяц), цена. Сам создаёт заявки ТО и поручения монтажнику на нужную дату.
  - **Деньги по объекту** — приход и расход, привязанные к заявке. Суммы хранятся в **копейках** (целым числом).
- **Быстро — это измеримо:** поиск клиента или объекта по любому слову из 10 000 записей — меньше 100 мс, открытие карточки — мгновенно с устройства, без ожидания сервера.
- Заявка с исполнителем = поручение: используются уже готовые статусы, отчёты с фото и голосовыми и напоминания.
